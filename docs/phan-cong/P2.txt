## 1. BỐI CẢNH KIẾN TRÚC (đọc kỹ trước khi code)

Dự án là hệ thống client-server TCP cho môn Lập trình mạng, gồm 4 project:

- QuanLyTro/QuanLyTro.Shared   — giao thức dùng chung: ActionNames.cs (danh sách
  action), DefaultPermissions.cs (ma trận quyền RBAC), RequestPacket/ResponsePacket
  (gói tin JSON), JsonDefaults (camelCase).
- QuanLyTro/QuanLyTro.Server   — console .NET 8, TCP listener cổng 8888. Toàn bộ
  nghiệp vụ nằm ở đây: Network/RequestRouter.cs (điều phối), Services/ (logic),
  Repositories/ (SQL), Data/Database.cs (ADO.NET MySqlConnector),
  Data/SchemaInitializer.cs (tạo bảng idempotent bằng CREATE TABLE IF NOT EXISTS),
  Security/ (đăng nhập PBKDF2, session token).
- QuanLyTro/QuanLyTro.Client   — WinForms + WebView2. Giao diện là HTML/CSS/JS
  trong QuanLyTro/Assets/wwwroot/, load qua https://app.quanlytro.local. Client
  KHÔNG có logic nghiệp vụ — mọi tính toán nằm ở server.
- QuanLyTro/QuanLyTro.Tests    — MSTest, DB riêng quanly_nhatro_test.

Luồng một request:
  JS (bridge.js postMessage requestId) → Form1.OnWebMessage (gắn token session)
  → TCP packet JSON 1 dòng → RequestRouter.HandleAsync:
      (1) action phải có trong DefaultPermissions.AllActionNames, không thì Deny
      (2) action public (PublicActions) không cần token, còn lại bắt buộc token
          hợp lệ → SessionInfo (chứa TaiKhoanId, VaiTro, KhuTroId — SCOPE KHU
          LUÔN LẤY TỪ SESSION, KHÔNG TỪ PAYLOAD)
      (3) DefaultPermissions.Allowed(vaiTro, action) — deny-by-default, action
          mới phải thêm vào BuildMatrix thì vai trò mới gọi được
      (4) dispatch qua switch → service method → repository → MySQL
  → ResponsePacket { requestId, Success, Message, Data } trả về cùng requestId.

GIAO THỨC BẮT BUỘC: JSON camelCase, mỗi packet 1 dòng kết thúc \n, mỗi request
bắt buộc có requestId (GUID), khung giới hạn 262144 byte/packet.

## 2. MÔI TRƯỜNG + CHẠY DỰ ÁN

Yêu cầu máy: .NET 8 SDK, MySQL 8 (Laragon — E:\Apps\laragon), Visual Studio 2022
hoặc VS Code.

1. git clone https://github.com/SmallFCraft/QuanLyNhaTro
   cd QuanLyNhaTro
   git checkout -b feat/m4-dien-nuoc-hoa-don   <-- LÀM TRÊN NHÁNH NÀY
2. Bật MySQL trong Laragon (Start All). Server TỰ TẠO DB quanly_nhatro + schema
   + seed tài khoản demo lần đầu chạy.
3. Chạy server:    dotnet run --project QuanLyTro/QuanLyTro.Server
4. Chạy client:    dotnet run --project QuanLyTro/QuanLyTro.Client
5. Chạy test:      dotnet test QuanLyTro/QuanLyTro.Tests

TÀI KHOẢN DEMO (đăng nhập màn hình login của client):
  chutro/chutro  — Chủ trọ, toàn quyền (thấy doanh thu)
  quanly/quanly  — Quản lý, chỉ thấy khu được gán (KHÔNG thấy doanh thu)
  letan/letan, nhanvien/nhanvien, congan/congan
  Khách thuê: đăng ký tự do bằng số CCCD 12 số ngay trên màn login.

LỖI THƯỜNG GẶP:
- MSB3021/MSB3027 file locked → tắt QuanLyTro.exe / QuanLyTro.Server.exe đang
  chạy rồi build lại.
- "Parameter '@xxx' must be defined" → SQL dùng biến @tên; AllowUserVariables=
  True đã có sẵn trong ServerOptions.cs — đừng xóa.
- INSERT không trả id → dùng cmd.LastInsertedId (xem ExecuteAsync trong
  Data/Database.cs — đã xử lý sẵn).
- Kiểm tra null MySQL: so sánh `is null or DBNull` — đừng Convert.ToInt32(null).
- Tiền tệ: dùng BIGINT (đồng VND, không lẻ) — đừng dùng float/double.

### 3b. Schema mới (QuanLyTro.Server/Data/SchemaInitializer.cs)
Thêm 2 bảng theo phong cách bảng có sẵn (CREATE TABLE IF NOT EXISTS, utf8mb4,
FK, index):

chi_so_dien_nuoc (
  id PK AUTO_INCREMENT,
  phong_id FK -> phong,
  ky_cuoc CHAR(7) NOT NULL,           -- 'yyyy-MM'
  dien_cu INT, dien_moi INT,          -- chỉ số đồng điện
  nuoc_cu INT, nuoc_moi INT,          -- khối nước
  hinh_thuc_nuoc ENUM('Khoi','DauNguoi') DEFAULT 'Khoi',
  so_nguoi INT NULL,                  -- khi tính theo đầu người
  ghi_so_luc DATETIME DEFAULT CURRENT_TIMESTAMP,
  nguoi_ghi_id FK -> tai_khoan,
  UNIQUE KEY uk_csdn (phong_id, ky_cuoc)   -- mỗi phòng 1 chỉ số mỗi kỳ
)

hoa_don (
  id PK AUTO_INCREMENT,
  phong_id FK -> phong,
  ky_cuoc CHAR(7) NOT NULL,
  tien_phong BIGINT, tien_dien BIGINT, tien_nuoc BIGINT, phi_khac BIGINT DEFAULT 0,
  tong_tien BIGINT NOT NULL,
  trang_thai ENUM('ChuaThu','DaThu') NOT NULL DEFAULT 'ChuaThu',
  ngay_dong DATETIME NULL, nguoi_thu_id FK -> tai_khoan NULL,
  ghi_chu VARCHAR(300) NULL,
  UNIQUE KEY uk_hd (phong_id, ky_cuoc), INDEX idx_hd_tt (trang_thai)
)

LƯU Ý: bảng cau_hinh_he_thong ĐÃ CÓ SẴN — đọc gia_dien/gia_nuoc từ cấu hình
(xem AccountService.GetConfigAsync để biết tên trường cấu hình).

### 3c. Service + Repository (mới: Services/DienNuocService.cs, Services/HoaDonService.cs, Repositories tương ứng)
Viết theo pattern có sẵn — mở Services/TenantService.cs + Repositories/
TenantRepository.cs đọc trước khi viết (cách đọc JsonElement, ném
ValidationException/NotFoundOrDeniedException, TransactionHelper).

Nghiệp vụ:
- DIEN_NUOC_LAY_KY_TRUOC { phongId, kyCuoc }: trả chỉ số kỳ trước để nhập kỳ
  này (dien_moi kỳ trước = dien_cu kỳ này). Không có kỳ trước → trả 0.
- DIEN_NUOC_GHI_SO { phongId, kyCuoc, dienMoi, nuocMoi, hinhThucNuoc?, soNguoi? }:
  UPSERT (INSERT ... ON DUPLICATE KEY UPDATE) chỉ số; validate dienMoi >= dienCu.
- HOA_DON_TAO { phongId, kyCuoc }: tính tiền phòng (từ hợp đồng HieuLuc — bảng
  hop_dong do Người 1 làm; NẾU CHƯA MERGE thì fallback đọc gia_thue từ bảng phong,
  ghi TODO đánh dấu chỗ hợp nhất sau M3), tiền điện = (dienMoi-dienCu) × giaDien,
  nước theo hinh_thuc_nuoc: Khoi → (nuocMoi-nuocCu) × giaNuoc; DauNguoi →
  soNguoi × giaNuocDauNguoi. Tổng = phòng + điện + nước + phí khác. Không tạo
  trùng (phòng, kỳ) — lỗi rõ ràng nếu trùng.
- HOA_DON_LAY_TAT_CA { kyCuoc, trangThai?, tuKhoa? }: danh sách kèm số phòng;
  QuanLy chỉ thấy hóa đơn phòng khu mình (scope từ session).
- HOA_DON_THANH_TOAN { hoaDonId, ghiChu? }: ChuaThu → DaThu, ghi ngay_dong +
  nguoi_thu_id = session. HÓA ĐƠN ĐÃ THU LÀ BẤT BIÊN: mọi action sửa hóa đơn
  DaThu phải bị từ chối (trừ HIỂN thị). Đây là quy tắc đề tài — test phải có.
- HOA_DON_CUA_TOI { page, soLuongMoiTrang } (KhachThue): hóa đơn của PHÒNG MÌNH
  (tra phòng từ lich_su_cu_tru/hợp đồng đang hiệu lực của khách), phân trang,
  kèm thông tin hợp đồng + chỉ số kỳ này để client render trang "Kỳ này".
- DOI_SOAT_CHAY { kyCuoc }: mô phỏng SePay — sinh vài giao dịch ngẫu nhiên
  khớp số hóa đơn ChuaThu rồi đánh dấu DaThu (nguoi_thu_id NULL, ghi_chu
  'Doi soat SePay'), trả { soGiaoDich, tongTienThu }. Đây là tính năng demo
  đối soát chuyển khoản — ghi chú rõ trong code là mô phỏng.
