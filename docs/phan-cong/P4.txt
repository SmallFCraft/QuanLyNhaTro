## 1. BỐI CẢNH KIẾN TRÚC (đọc kỹ trước khi code)

Dự án là hệ thống client-server TCP cho môn Lập trình mạng, gồm 4 project:

- QuanLyTro/QuanLyTro.Shared   — giao thức dùng chung: ActionNames.cs (danh sách
  action), DefaultPermissions.cs (ma trận quyền RBAC), RequestPacket/ResponsePacket
  (gói tin JSON), JsonDefaults (camelCase).
- QuanLyTro/QuanLyTro.Server   — console .NET 8, TCP listener cổng 8888. Toàn bộ
  nghiệp vụ nằm ở đây: Network/RequestRouter.cs (điều phối), Services/ (logic),
  Repositories/ (SQL), Data/Database.cs (ADO.NET MySqlConnector),
  Data/SchemaInitializer.cs (tạo bảng idempotent bằng CREATE TABLE IF NOT EXISTS),
  Security/ (đăng nhập PBKDF2, session token).
- QuanLyTro/QuanLyTro.Client   — WinForms + WebView2. Giao diện là HTML/CSS/JS
  trong QuanLyTro/Assets/wwwroot/, load qua https://app.quanlytro.local. Client
  KHÔNG có logic nghiệp vụ — mọi tính toán nằm ở server.
- QuanLyTro/QuanLyTro.Tests    — MSTest, DB riêng quanly_nhatro_test.

Luồng một request:
  JS (bridge.js postMessage requestId) → Form1.OnWebMessage (gắn token session)
  → TCP packet JSON 1 dòng → RequestRouter.HandleAsync:
      (1) action phải có trong DefaultPermissions.AllActionNames, không thì Deny
      (2) action public (PublicActions) không cần token — hiện là { DANG_NHAP,
          KHACH_THUE_DANG_KY }; action public mới phải thêm vào bộ này
      (3) với action có token: SessionInfo (TaiKhoanId, VaiTro, KhuTroId —
          SCOPE KHU LUÔN LẤY TỪ SESSION, KHÔNG TỪ PAYLOAD)
      (4) DefaultPermissions.Allowed(vaiTro, action) — deny-by-default
      (5) dispatch qua switch → service method → repository → MySQL
  → ResponsePacket { requestId, Success, Message, Data } trả về cùng requestId.

GIAO THỨC BẮT BUỘC: JSON camelCase, mỗi packet 1 dòng kết thúc \n, mỗi request
bắt buộc có requestId (GUID), khung giới hạn 262144 byte/packet.

## 2. MÔI TRƯỜNG + CHẠY DỰ ÁN

Yêu cầu máy: .NET 8 SDK, MySQL 8 (Laragon — E:\Apps\laragon), Visual Studio 2022
hoặc VS Code.

1. git clone https://github.com/SmallFCraft/QuanLyNhaTro
   cd QuanLyNhaTro
   git checkout -b feat/m5-lich-luu-tru   <-- LÀM TRÊN NHÁNH NÀY
2. Bật MySQL trong Laragon (Start All). Server TỰ TẠO DB quanly_nhatro + schema
   + seed tài khoản demo lần đầu chạy.
3. Chạy server:    dotnet run --project QuanLyTro/QuanLyTro.Server
4. Chạy client:    dotnet run --project QuanLyTro/QuanLyTro.Client
5. Chạy test:      dotnet test QuanLyTro/QuanLyTro.Tests

TÀI KHOẢN DEMO:
  chutro/chutro, quanly/quanly, letan/letan, nhanvien/nhanvien, congan/congan;
  khách thuê tự đăng ký bằng CCCD.

LỖI THƯỜNG GẶP:
- MSB3021/MSB3027 file locked → tắt process QuanLyTro.exe/Server.exe chạy dở.
- "Parameter '@xxx' must be defined" → AllowUserVariables=True đã có trong
  ServerOptions.cs — đừng xóa.
- INSERT trả id → cmd.LastInsertedId (Data/Database.cs đã xử lý sẵn).
- Null MySQL: so sánh `is null or DBNull`.
- Action public: chỉ thêm vào PublicActions khi THẬT SỰ không cần đăng nhập —
  sai chỗ này là lỗ hổng bảo mật (xem Network/RequestRouter.cs PublicActions).

### 3b. Schema mới (QuanLyTro.Server/Data/SchemaInitializer.cs)

dat_lich_xem_phong (
  id PK AUTO_INCREMENT,

  INDEX idx_dl_dt (thoi_gian), UNIQUE KEY uk_dl (phong_id, thoi_gian, so_dien_thoai)

lich_kiem_tra (

### 3c. Service + Repository (mới: Services/DatLichService.cs, Services/LichKiemTraService.cs, Services/LuuTruService.cs + repositories)
Pattern mẫu: Services/TenantService.cs + Repositories/TenantRepository.cs — đọc
trước khi viết (JsonElement, ValidationException, NotFoundOrDeniedException,
TransactionHelper, scope khu).

Nghiệp vụ:
- PHONG_LAY_TRONG_PUBLIC (PUBLIC — không token): trả danh sách phòng Trống
  { phongId, soPhong, tenKhu, giaThue } để trang public render lưới phòng.
  CHỈ TRẢ trường an toàn — không có gì về tài khoản/CCCD.
- KHACH_THUE_DAT_LICH (PUBLIC — không token): { phongId, hoTen, soDienThoai,
  thoiGian } → validate (phòng phải Trống, thời gian tương lai, BR 3 yêu cầu
  chờ/ngày/số điện thoại) → tạo dat_lich_xem_phong.
- LICH_KIEM_TRA_LAY: Lễ tân/ChuTro — danh sách lịch kiểm tra (kèm trạng thái).
  Khi một lịch đặt được duyệt, sinh lich_kiem_tra tương ứng (hoặc duyệt trực
  tiếp trên lich_kiem_tra do lễ tân thêm tay).
- LICH_KIEM_TRA_DUYET / TU_CHOI { lichId, lyDoTuChoi? }: Lễ tân/ChuTro.
- LICH_KIEM_TRA_NHAN_VIEN: trả danh sách nhân viên (vai trò NhanVien, kèm
  chuyen_mon) để lễ tân chọn gán.
- LICH_KIEM_TRA_GAN_NV { lichId, nhanVienId }: gán việc → trang_thai DaDuyet
  (đã duyệt chờ nhận).
- LICH_KIEM_TRA_CUA_TOI: NhanVien — việc được gán cho mình.
- LICH_KIEM_TRA_NHAN_VIEC { lichId }: nhân viên nhận → DangLam.
- LICH_KIEM_TRA_HOAN_THANH { lichId, ketQua }: nhân viên ghi kết quả →
  HoanThanh.
- XUAT_HO_SO_TAM_TRU { cccd?, hoTen?, soDienThoai?, soPhong?, tuKhoa? } (CongAn,
  CHỈ ĐỌC): tra cứu hồ sơ khách đang lưu trú — ít nhất 4 ký tự cho từng tiêu chí
  có nhập (theo đề tài: CCCD >= 4 số). Trả danh sách { hoTen, cccd (MASK bớt
  4 số cuối khi render ở trang public — ở shell Công an trả đầy đủ vì đã đăng
  nhập), soPhong, tenKhu, ngayBatDauTamTru, soDienThoai }. Format CSV cho xuất:
  trả chuỗi CSV trong Data, client tải xuống bằng blob.
- LICH_SU_CU_TRU_LAY { khachThueId?/phongId? }: xem lịch sử ở lại/ra (bảng sẵn).
